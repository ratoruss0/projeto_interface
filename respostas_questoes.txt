20 perguntas para homologar e preparar o Sistema Academico para uso

Professor: Felipe Douglas
Projeto: Sistema Academico

1- R: Sim. O sistema possui uma proposta clara de gerenciamento acadêmico, permitindo o controle de alunos, professores, disciplinas e matrículas de maneira organizada e intuitiva.

2- R:
Cadastro de alunos;
Cadastro de professores;
Cadastro de disciplinas;
Matrículas;
Pesquisa de registros;
Emissão de relatórios em JSON e PDF.

3- R: Sim. O sistema realiza validações para impedir envio de formulários vazios ou incompletos antes da gravação no banco de dados.

4- R: Sim. Foram implementadas validações para evitar duplicidade de dados únicos

5- R: Sim. A pesquisa aceita nomes completos, trechos do nome e realiza buscas sem diferenciação entre letras maiúsculas e minúsculas.

6- R: Sim. O sistema valida as matrículas existentes antes de cadastrar uma nova, impedindo duplicidade na mesma disciplina.

7-  R: Sim. O processo de remoção foi implementado de forma controlada, permitindo manter consistência e histórico conforme a regra de negócio definida.

8- R: Sim. O método segue as regras estabelecidas, garantindo remoção adequada sem comprometer registros relacionados no sistema.

9- R: Sim. O sistema apresenta mensagens informativas ao usuário, facilitando o entendimento das operações realizadas.

10- R: Sim. A interface foi desenvolvida com responsividade básica, permitindo adaptação em diferentes tamanhos de tela.

11- R: Sim. Os relatórios exibem informações completas e organizadas para conferência e acompanhamento acadêmico.

12- R: Sim. O arquivo schema.sql contém toda a estrutura necessária para criação das tabelas e configuração inicial do banco.

13- R: Sim. O sistema possui suporte ao SQLite como alternativa local para execução e testes.

14- R:Sim. A documentação apresenta os passos necessários para instalação, configuração e execução do sistema.

15- R: Sim. Foram realizados testes manuais cobrindo as principais funcionalidades do sistema.

16- R: Sim. O sistema passou por testes com diferentes cenários de entrada para validar seu comportamento e robustez.

17- R: Sim. Os textos da interface seguem padronização em português para facilitar o uso e entendimento do sistema.

18- R: Sim. Foram implementadas validações básicas para impedir entradas inválidas e minimizar erros operacionais.

19- R: Parcialmente. O sistema já possui estrutura para configuração segura, porém recomenda-se revisar variáveis sensíveis e garantir o modo debug desativado em produção.

20- R: Sim. A homologação final ficará sob responsabilidade do professor, considerando funcionamento completo das funcionalidades obrigatórias, estabilidade e validação dos testes realizados.
